## Next steps, in order

### 1. Extend the watchdog to check status, not just recency  ← START HERE

**This is a gap I introduced today and did not close.** `SERVICE_HEARTBEAT` in
`scripts/offbox_watchdog.py` asks when a service last *ran*. It does not ask
whether the run *succeeded*.

That blind spot is not hypothetical: `notification_scanner` wrote a
`pipeline_runs` row every five minutes for seventeen days while **every one of
4,182 runs failed**. The check added today would have reported it green
throughout.

The fix: `pipeline_runs` already has a `status` column (`'ok'` / `'failed'`).
Extend the `SERVICE_HEARTBEAT` query to select the latest status per service
and fail when the most recent run is not `ok`, keeping the existing staleness
check alongside it — a service can be both stale and failing, and those are
different problems with different causes.

Verify by running `/usr/bin/python3 scripts/offbox_watchdog.py --dry-run` from
the Mini. `--dry-run` never sends an alert and is safe to run repeatedly.
